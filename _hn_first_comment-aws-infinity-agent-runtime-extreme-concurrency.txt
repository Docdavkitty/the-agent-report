One way to compare the two execution models is byte-seconds, rather than “agents per machine.” At the rerun's 105.6 KB per idle agent, keeping that state in RAM for a six-hour wait is about 2.28 GB·s; for a three-day wait it is about 27.4 GB·s. A blocking worker with a footprint of P MB consumes 21,600 × P MB·s over six hours, or 259,200 × P MB·s over three days. The benchmark does not report P, so it cannot supply a precise savings ratio. And if Infinity's state is in a durable store rather than RAM, the relevant bill becomes storage retention plus reads, writes, queueing, and wake-up compute—not zero.

This is why the serverless integration matters more than the Pi analogy. Lambda can run a bounded slice, enqueue or dispatch the tool work, and terminate; the later event starts another slice. That makes function time track actual work instead of the entire webhook or approval delay. It is not literally “one event, one fixed price”: every resume can trigger model inference, queue operations, and persistence, and model tokens may dominate the bill. But the architecture stops charging compute for the hours in which the agent is doing nothing.

The slice abstraction also leaves an unresolved state-management question. The benchmark's roughly 5 KB of added history per turn implies about 2.5 MB of transcript growth after 500 turns if that rate held linearly—an extrapolation, not a measurement at 500. Compaction can reduce retained context, but it must preserve the details needed for later tool decisions; aggressive summarization risks changing behavior, while conservative summarization gives back the memory savings. What should a production runtime optimize first: bytes retained, fidelity of the agent's history, or predictable serverless cost?
